# Offline reverse-engineering workbench

This runbook defines the reproducible, offline workshop used to understand the
native PE32/x86 Airfix Dogfighter v1.01 program and turn confirmed behavior into
independently written portable C++20.

Ghidra is the canonical static-analysis database and repeatable decompiler.
Rizin is the second, scriptable implementation used for machine-readable
metadata, boundaries, references, search, signatures, and comparison. Cutter is
the local GUI for Rizin. Binary Ninja Free Desktop is a manual independent
check for difficult functions. x32dbg is reserved for later controlled dynamic
observation.

## Non-negotiable safety boundary

- Analyze only files copied from an installation owned by the operator.
- Keep the source installation read-only. Never import, unpack, patch, debug, or
  launch a file in place.
- Verify every source and copy against
  [source-manifest.sha256](../evidence/source-manifest.sha256).
- Keep the computer offline from analysis services while private inputs are
  open. Never upload an original file, extracted module, converted asset,
  database, dump, trace, or pseudocode bundle to Binary Ninja Cloud or any
  other internet service.
- Run tools as the ordinary user. Do not elevate a game executable, installer,
  decompiler, Cutter, or debugger.
- Do not enable Rizin write mode, debugger mode, remote servers, debuginfod, or
  PDB download for this workflow.
- Begin dynamic analysis only in a controlled, snapshot-capable Windows
  environment. The first phase permits observation and breakpoints, but no
  file patching, memory patching, injection, or saved modified executable.
- Never commit original/derived binaries, tool databases, local paths, dumps,
  traces, screenshots, signatures made from private code, or vendor-licensed
  files.

Exact versions, upstream links, hashes, signatures, licenses, and real
installation states are locked in [LOCK.md](LOCK.md).

## Tool roles

| Tool | Role | Evidence independence and limitations |
|---|---|---|
| Ghidra Headless/Desktop | Primary program database, type recovery, decompilation, deterministic reports | Canonical static result; local `.gpr/.rep` remain private |
| Rizin + `rzpipe` | Scripted PE32/x86 inventory, boundaries, calls, data references, searches, FLIRT signatures, diffs, normalized JSON | Independent analysis implementation from Ghidra; autogenerated names and types remain hypotheses |
| Cutter | Manual graph/disassembly UI and optional bundled `rz-ghidra` pseudocode | Uses Rizin underneath, so it is not a third independent source |
| Binary Ninja Free Desktop | Manual cross-check of ambiguous boundaries, ABI, calls, globals, and pseudocode | Independent static implementation; Free has no API/plugins; local Desktop only; installed and awaiting confirmed offline settings |
| x32dbg | Later controlled observation of the 32-bit process | Dynamic evidence only after environment approval; no patching in the initial phase |

dnSpy and ILSpy target managed .NET assemblies, and W32Dasm adds no useful
capability beyond the locked native PE32/x86 tools. They are intentionally not
installed.

## Prepare a verified working copy

The copy script requires an explicit source root and explicit manifest entries.
It does not support "copy everything", rejects traversal/reparse points, creates
files without overwriting, and verifies the source before and after the copy:

```powershell
./tools/Prepare-ReWorkingCopy.ps1 `
  -SourceRoot '<OWNED_INSTALLATION_ROOT>' `
  -ManifestEntry @(
    'Cc.dll',
    'Dogfighter.exe',
    'Game\Types\AirCraft.type'
  )
```

The output is placed below
`analysis/work-copies/manifest-<MANIFEST_SHA256>/`. Repeating the command reuses
only an existing byte-identical copy; a conflict is a hard failure. The source
path is never written into a report or repository file.

Before starting a tool, independently confirm one selected copy if needed:

```powershell
Get-FileHash -Algorithm SHA256 `
  -LiteralPath 'analysis\work-copies\manifest-<HASH>\Cc.dll'
```

Do not remove the copy while a tool has it open. Recreate it through the script
instead of copying from memory or an unverified extraction.

## Canonical Ghidra reports

After the immutable first import, address a program by its literal Ghidra
domain-file name rather than passing the private source path again:

```powershell
./tools/Invoke-GhidraAnalysis.ps1 `
  -ProgramName 'AirCraft.type' `
  -PostScript 'ExportFunctionInstructions.java' `
  -PostScriptArguments @('10003F40') `
  -ReportSuffix 'flight-instructions'
```

Use the exact locked Ghidra/JDK versions. Preserve the raw local report and
publish only concise observations, contracts, constants, and evidence IDs.
See [../RE-WORKFLOW.md](../RE-WORKFLOW.md) for all available exporters.

## Repeatable Rizin commands

Set these shell variables to a verified portable installation and one verified
copy. They are deliberately local and must never be committed:

```powershell
$rizinBin = '<RIZIN_BIN_DIRECTORY>'
$copy = 'analysis\work-copies\manifest-<HASH>\Cc.dll'
```

PE identity, sections, imports, exports, and strings:

```powershell
& "$rizinBin\rz-bin.exe" -Ij $copy
& "$rizinBin\rz-bin.exe" -Sj $copy
& "$rizinBin\rz-bin.exe" -ij $copy
& "$rizinBin\rz-bin.exe" -Ej $copy
& "$rizinBin\rz-bin.exe" -zj $copy
```

Function discovery and one normalized read-only session:

```powershell
& "$rizinBin\rizin.exe" -N -q -e scr.color=false `
  -c 'aaa; aflj; q' $copy
& "$rizinBin\rizin.exe" -N -q -e scr.color=false `
  -c 'aaa; s 0x1001FDD0; afij; pdfj; agfj; axfj; q' $copy
```

Searches:

```powershell
& "$rizinBin\rz-find.exe" -j -s 'DirectInputCreateA' $copy
& "$rizinBin\rz-find.exe" -j -w 'example wide string' $copy
& "$rizinBin\rz-find.exe" -j -x '558bec' $copy
& "$rizinBin\rz-find.exe" -j -I 'DirectInputCreateA' $copy
```

Function-aware diff and a private FLIRT signature:

```powershell
& "$rizinBin\rz-diff.exe" -C -B -j -t functions `
  -0 0x1001FDD0 -1 0x1001FDD0 <COPY_A> <COPY_B>
& "$rizinBin\rz-sign.exe" -aa `
  -o 'artifacts\rizin\private-module.sig' $copy
```

The `.sig` file derives from private code and must remain under ignored
`artifacts/`. Do not use `rz-bin -PP` or `rz-bin -dd`; those modes may contact
symbol/debug-information services.

### Deterministic `rzpipe` report

Install only the pinned dependency into an ignored virtual environment before
opening a private input:

```powershell
python -m venv analysis\tools\rzpipe-venv
analysis\tools\rzpipe-venv\Scripts\python.exe -m pip install `
  --require-hashes -r tools\rizin\requirements.txt
```

Then generate one function report through the safety wrapper:

```powershell
./tools/Invoke-RizinAnalysis.ps1 `
  -InputFile 'analysis\work-copies\manifest-<HASH>\Cc.dll' `
  -FunctionId 'FN-CC-0001FDD0' `
  -Rva '0x0001FDD0' `
  -ExpectedSha256 '<MODULE_SHA256>' `
  -RizinHome $rizinBin `
  -PythonPath 'analysis\tools\rzpipe-venv\Scripts\python.exe'
```

The wrapper accepts only a canonical file below `analysis/work-copies`,
checks its hash before and after analysis, opens Rizin read-only with user
startup configuration disabled, anchors the request by canonical RVA, records
image-base/VA observations, and validates the resulting
`airfix.re.rizin-function.v1` JSON under `artifacts/rizin`. Optional pseudocode
may be requested with Cutter's verified Sleigh directory; it remains a
Rizin-family result and is labeled as such.

Automatic function discovery is the default and a missing `afij` result fails
closed. After Ghidra or instruction evidence independently confirms the exact
entry RVA, an analyst may repeat the command with `-CreateMissingFunction`.
That opt-in creates only an in-memory Rizin analysis function at the requested
address and records `discovery.automatic=false` and
`discovery.created_at_requested_va=true` in the report. It does not enable
write mode or modify the working copy.

## Manual Cutter procedure

1. Verify the Cutter archive against [LOCK.md](LOCK.md) before first use.
2. Start `cutter.exe` as the ordinary user and open only a verified working
   copy.
3. Store every project/database below `analysis/cutter-projects`.
4. Record the analysis profile and exact address. Disable write/debug modes.
5. Use graphs and the bundled `rz-ghidra` view to investigate differences from
   the scripted report. Treat the result as the same Rizin evidence source.
6. Close the input before enabling network access for an unrelated task.

## Manual Binary Ninja Free procedure

The owner personally accepted the current Free license and installed the
hash-verified Desktop build. Before the first private input:

1. Use the official per-user Desktop installer without administrator rights.
2. Launch it once without a game file. Disable update/channel/release-note
   checks, the plugin manager, automatic PDB downloads, external URLs, WARP
   networking, and crash reporting before analysis. The vendor's downloadable
   product privacy page explicitly does not cover the Free edition, so conduct
   the pilot offline as an additional control.
3. Open only a verified working copy in the native Desktop application.
4. Never choose a Cloud/open-in-browser/upload workflow and never send a
   database or original-derived file to Vector 35 or another service.
5. Save `.bndb` only below `analysis/binary-ninja-projects`.
6. Do not install plugins and do not attempt API automation; Free does not
   provide those facilities.
7. For each pilot function, record start/end, proposed ABI/signature, direct
   calls, global/data accesses, and a short pseudocode summary. Do not copy a
   full decompiler listing into Git.

## Controlled x32dbg phase

The portable package contains both architectures; use only
`release/x32/x32dbg.exe` for this 32-bit game. Do not use `x96dbg.exe`, whose
launcher offers shell integration.

Dynamic work begins only after a separate environment checklist confirms:

- a disposable or snapshot-capable Windows VM;
- networking disabled unless a specific observation requires it;
- verified working copies and a clean snapshot;
- ordinary-user execution;
- original installation unavailable or mounted read-only;
- output confined to `analysis/x64dbg-workspace`;
- memory and file patching disabled for the first experiment.

The first experiment may observe module loads, the system breakpoint,
read/execute breakpoints, call stacks, registers, and copied memory values. It
must not assemble, patch, inject, write a modified executable, register a shell
extension, or run the game/installer elevated. Record `.dd32` and `.trace32`
files as private local artifacts.

## Recording discoveries

Use stable IDs and normalize every address:

```text
Function:   FN-CC-0001FDD0
Module:     CC / Cc.dll
Build:      SHA256:<64 hex>
Image base: 0x10000000
RVA:        0x0001FDD0
VA:         0x1001FDD0
File off:   0x???????? (tool-derived, build-specific)
State:      located|decompiled|understood|specified|implemented|verified
Evidence:   EV-YYYYMMDD-NNN
Confidence: 0 unknown | 1 low | 2 medium | 3 high
Hypothesis: H1 — precise falsifiable statement
Alternative:H2 — competing statement and distinguishing observation
```

Structures use `TY-<MODULE>-<RVA>` when tied to a vtable/type identity. Fields
remain offset-based until meaning is proved:

```text
TY-AIRCRAFT-00011020 +0x01A4: float, read by FN-..., working name
Observation: exact instruction/data-flow fact
Interpretation: proposed semantic meaning
Confidence: 2
```

Globals use `GL-<MODULE>-<RVA>`. A function comparison records, per tool:

| Field | Required value |
|---|---|
| Boundary | start VA/RVA, end-exclusive VA/RVA, instruction/body size |
| Signature | proposed return, calling convention, receiver, parameters; mark inference |
| Calls | direct call-site RVA and target stable ID/name/address |
| Globals | access-site RVA, target RVA, width, read/write/unknown |
| Pseudocode | concise behavioral summary, not a pasted listing |
| Reliability | tool result, supporting raw bytes/xrefs, unresolved disagreement |

## Three-tool comparison procedure

1. Freeze the module SHA-256, image base, tool versions, function ID, and exact
   requested RVA.
2. Export Ghidra instructions and decompilation from the locked local project.
3. Produce a fresh Rizin/rzpipe report from the same verified copy without
   importing Ghidra names or types.
4. Manually inspect the same RVA in Binary Ninja Free without importing either
   previous database.
5. Compare the five required fields. Separate raw instruction/xref agreement
   from decompiler type/name agreement.
6. Resolve boundary disputes using entry references, control-flow reachability,
   stack cleanup, return sites, adjacent function references, unwind/export
   metadata where present, and exact bytes.
7. Resolve signatures using call sites and ABI behavior before trusting any
   generated C type. Record alternatives if hidden `this`, structure return, or
   stack width is uncertain.
8. Prefer independently matching raw bytes and xrefs over attractive
   pseudocode. Ghidra remains the canonical database; an unresolved disagreement
   stays explicit instead of being majority-voted away.
9. Assign a new evidence ID and update the function catalog/system contract.
   Static agreement alone does not raise a claim to confidence 3.

## Promoting knowledge into C++20

Confirmed knowledge crosses into production only as an independently expressed,
platform-neutral behavioral contract:

1. Describe inputs, outputs, state, ordering, units, precision, failure
   behavior, ownership, and known unknowns.
2. Identify which claims are observations and which are interpretations.
3. Define a synthetic scenario or parity measurement before implementation.
4. Implement maintainable C++20 without x86 calling conventions, decompiler
   temporaries, raw global addresses, undefined behavior, or copied vendor code
   structure.
5. Keep UIKit, Game Controller, and Metal behind Objective-C++ adapters; no
   Apple types enter the portable core.
6. Link source/tests to a system contract or scenario ID, not to a pasted
   disassembly.
7. Re-run portable builds/tests and the public-boundary scanner. Update the
   catalog, system note, status, log, and parity matrix only to the level the
   evidence supports.

## Files that must remain outside Git

- original executables, DLLs, type/mode modules, archives, assets, media, and
  locally converted `.afpack` packages;
- `analysis/work-copies`, `analysis/tool-cache`, and expanded vendor tools;
- Ghidra `.gpr/.rep`, Binary Ninja `.bndb`, Rizin `.rzdb`, Cutter projects;
- x32dbg `.dd32/.dd64`, backups, `.trace32/.trace64`, dumps, and screenshots;
- Rizin/Ghidra raw reports, private FLIRT signatures, decompiler exports, and
  memory captures;
- local Python virtual environments and package caches;
- local installation paths, usernames, device IDs, signing identities,
  certificates, profiles, signed IPAs, and credentials;
- any file whose license does not permit redistribution in this repository.

Only reusable scripts, version/hash locks, concise evidence, behavioral
contracts, synthetic fixtures, and independently written source code belong in
the public project.
