# FMT-AFPACK — private iOS content container

**State:** version 1 container, parser, verifier, and local writer implemented;
iOS importer pending

**Confidence:** design contract (not an original Airfix format)

## Purpose and trust boundary

AFPACK is a new project-owned container for moving a lawful owner's local game
data into the data-less iOS application. It is not used by the original game
and is not intended to reconstruct UDSP. Version 1 stores original `.up`
archives as opaque entries so conversion can remain incremental.

The public repository, GitHub Actions inputs/caches, application bundle, and CI
artifacts must never contain an `.afpack` or original/converted game payload.
The Windows converter reads the owner's installation and writes the pack only
to a user-selected local path. The iOS application imports it into its private
Application Support directory.

AFPACK provides structural validation and SHA-256 integrity, not publisher
authentication or DRM. A user who can replace both a pack and its manifest is
inside the local trust boundary.

## Version 1 goals

- deterministic, byte-for-byte reproducible output for identical inputs;
- 64-bit offsets and sizes;
- bounded metadata reads without buffering large payloads;
- streaming generation, verification, and import;
- normalized UTF-8 logical paths independent of Windows paths;
- no outer compression, because source UDSP payloads are already compressed;
- enough entry typing to introduce converted assets later without changing the
  transport format.

All integers are unsigned little-endian. Every reserved field and all flags are
zero in version 1.

## Physical layout

```text
0x0000                    80-byte header
entryTableOffset          fixed-size entry records
stringTableOffset         concatenated UTF-8 paths (not NUL-terminated)
                          zero padding to 16-byte alignment
dataOffset                entry payloads, each beginning at 16-byte alignment
archiveSize               end of file
```

Entry records are strictly sorted by their raw normalized UTF-8 path bytes.
Payload order is the same as entry order. Padding bytes written by the canonical
writer are zero.

## Header (80 bytes)

| Offset | Size | Field | Version 1 value/meaning |
|---:|---:|---|---|
| `0x00` | 4 | `magic` | ASCII `AFPK` |
| `0x04` | 2 | `versionMajor` | `1` |
| `0x06` | 2 | `versionMinor` | `0` |
| `0x08` | 4 | `headerSize` | `80` |
| `0x0C` | 4 | `flags` | `0` |
| `0x10` | 4 | `entryCount` | number of entry records |
| `0x14` | 4 | `reserved` | `0` |
| `0x18` | 8 | `entryTableOffset` | `80` |
| `0x20` | 8 | `entryTableSize` | `entryCount * 80` |
| `0x28` | 8 | `stringTableOffset` | immediately after entry table |
| `0x30` | 8 | `stringTableSize` | bytes, excluding alignment padding |
| `0x38` | 8 | `dataOffset` | aligned beginning of payload region |
| `0x40` | 8 | `archiveSize` | exact physical file size |
| `0x48` | 8 | `reserved` | `0` |

## Entry record (80 bytes)

| Offset | Size | Field | Meaning |
|---:|---:|---|---|
| `0x00` | 8 | `pathOffset` | relative byte offset in string table |
| `0x08` | 4 | `pathSize` | UTF-8 byte length, without terminator |
| `0x0C` | 2 | `kind` | entry kind below |
| `0x0E` | 2 | `flags` | `0` |
| `0x10` | 8 | `dataOffset` | absolute, 16-byte-aligned file offset |
| `0x18` | 8 | `storedSize` | bytes physically stored |
| `0x20` | 8 | `contentSize` | logical byte size |
| `0x28` | 32 | `sha256` | SHA-256 of stored/logical bytes |
| `0x48` | 8 | `reserved` | `0` |

Version 1 requires `storedSize == contentSize`; compression/encryption flags are
not defined. A digest containing 32 zero bytes is invalid.

### Entry kinds

| Value | Name | Use |
|---:|---|---|
| `1` | manifest | exactly one `manifest.json` |
| `2` | source archive | an original `.up` kept opaque |
| `3` | localization | localized source/intermediate content |
| `4` | video | optional supported video asset |
| `5` | converted asset | documented project-owned intermediate format |

Kinds do not grant permission to execute data. The importer treats every entry
as bytes and must never load source PE modules or scripts.

## Path rules

Paths are non-empty UTF-8, relative, `/`-separated, and canonical. Reject:

- a leading slash, drive/URI colon, or backslash;
- empty, `.` or `..` components;
- ASCII control bytes;
- invalid, overlong, surrogate, or out-of-range UTF-8;
- duplicate or non-strictly-sorted paths.

The first converter allowlist is deliberately narrower than the container:

- `manifest.json` generated by the converter;
- `source/Resource.up`;
- one selected `localization/<Language>.up` when available;
- explicitly supported videos only after their playback path exists.

Original `.exe`, `.icd`, `.dll`, `.mode`, `.type`, configuration, save, and
unknown loose files are denied. Runtime plugin behavior is reconstructed as
native compile-time registries; Windows binaries are never imported to iOS.

## Manifest version 1

`manifest.json` is UTF-8 JSON produced deterministically (stable property and
entry order, LF line endings, no timestamps). Its minimum logical schema is:

```json
{
  "schema": "airfix.afpack.manifest",
  "version": 1,
  "game": {
    "id": "airfix-dogfighter",
    "sourceVersion": "1.01"
  },
  "converter": {
    "version": "0.1.0",
    "commit": "<source commit or unknown>"
  },
  "locale": "en",
  "capabilities": {
    "music": false,
    "multiplayer": false,
    "editors": false
  },
  "entries": [
    {
      "path": "source/Resource.up",
      "kind": "source-archive",
      "size": 170642453,
      "sha256": "<64 lowercase hex characters>"
    }
  ]
}
```

The manifest entry list excludes `manifest.json` itself. Header record digests
are authoritative for byte verification; matching manifest values provide a
human-readable audit and must agree during import.

Because the original CD/audio tracks are unavailable, `music` is always false
for the accepted v1 source set. Missing music is a supported configuration, not
an import failure.

## Validation and atomic import

The importer performs these steps without trusting filenames or declared sizes:

1. copy the selected pack into a unique staging file under Application Support;
2. read only the header and metadata, validate all checked arithmetic, ranges,
   alignment, path rules, kinds, uniqueness, and non-overlapping payloads;
3. stream every payload through SHA-256 and compare its entry digest;
4. parse `manifest.json`, require supported schema/game/converter compatibility,
   and compare its entry audit with the table;
5. validate nested source archives through bounded readers before activation;
6. flush/close the staging file, atomically rename it to a versioned final name,
   and atomically update the active-pack pointer;
7. delete the previous pack only after the new one has opened successfully.

Cancellation, backgrounding, insufficient disk, malformed input, or digest
failure removes staging data and leaves the previous active pack untouched.
Diagnostics may log logical paths, sizes, and digests, but never payload bytes.

## Portable implementation

- metadata parser: `src/airfix/package/AfPack.*`;
- deterministic writer: `src/airfix/package/AfPackWriter.*`;
- allowlisted local CLI: `afpack-create`;
- portable streaming SHA-256: `src/airfix/crypto/Sha256.*`;
- synthetic valid/malformed and limit tests: `tests/AfPackTests.cpp` and
  `tests/AfPackLimitsTests.cpp`;
- iOS streaming verifier/importer: pending.

`Pack::open` reads the fixed header plus metadata through `dataOffset`; it does
not buffer payloads. `Pack::parse` exists for synthetic tests and small trusted
buffers. SHA-256 validation is intentionally a separate streaming operation at
the converter/import boundary.

Both entry points accept explicit `ParseLimits`. The default ceiling is 512 MiB
per archive, 8 MiB of metadata, 4,096 entries, 1,024 UTF-8 bytes per path, 4 MiB
for the string table, and 384 MiB per payload. These checks run before metadata
allocation or payload reads. `Pack::readEntry` additionally requires a caller
byte limit and verifies the returned bytes against the entry SHA-256, so a
same-size file replacement cannot silently return data belonging to different
metadata.

The initial CLI accepts only an installation root, one of the four observed
language names, and an output path. It constructs the two-entry allowlist
internally, validates both nested UDSP archives before writing, refuses to
replace existing output, writes through a `.partial` sibling, reopens and
verifies every digest and nested archive, and then performs the final rename.

An end-to-end local validation produced and verified a 192,755,765-byte English
pack with three entries (`manifest.json`, `Resource.up`, and `English.up`), then
removed that temporary pack. No original bytes entered Git or GitHub Actions.

## Security test corpus

Keep synthetic tests for truncated headers/tables, overflow, impossible archive
size, invalid UTF-8, traversal, duplicates/sort order, unknown kinds/flags,
zero digest, payload overlap, unaligned/out-of-range payload, missing/duplicate
manifest, manifest-table disagreement, digest mismatch, cancellation, disk-full
rollback, and nested decompression output limits.
